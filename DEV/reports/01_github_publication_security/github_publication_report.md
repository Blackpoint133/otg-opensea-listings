## Диагностика запуска в той же задаче

Классификация: C — сбой окружения Codex Windows sandbox (рабочая классификация;
исключительность для sandbox ещё требует контрольного запуска вне Codex).

TEST EXECUTION BLOCKED BY CODEX WINDOWS SANDBOX ENVIRONMENT

Прямой вызов os.userInfo() в чистом Node, без импорта проекта, воспроизводит
ERR_SYSTEM_ERROR / uv_os_get_passwd / ENOMEM. os.homedir() работает.
tsx 4.23.5 не запускает даже --version: при загрузке модуля
node_modules/tsx/dist/temporary-directory-BDDVQOvU.mjs:1:84 выполняется
os.userInfo().username. На Windows отсутствует process.geteuid, поэтому выбирается
эта ветка определения имени временного каталога. В src, tests, scripts и
package.json обращений os.userInfo, userInfo(, uv_os_get_passwd и username-sync нет.
Сбой происходит до импорта тестов; это ENVIRONMENT / TOOLING, дефект проекта
не установлен. Свободно 3,674 ГиБ из 15,999 ГиБ, RSS Node около 43 МиБ:
фактическое исчерпание RAM не подтверждается.

Документация OpenAI описывает отдельные sandbox-пользователи и ограниченные
Windows-токены: https://learn.chatgpt.com/docs/windows/windows-sandbox.
Она подтверждает механизм изоляции, но не доказывает конкретную причину ENOMEM.
Непосредственно доказан отказ Node/libuv получать информацию пользователя в
текущем окружении. Точный отказ Windows API и причинная роль ограниченного
токена не измерены; утверждать sandbox-only без внешнего сравнения нельзя.

## Герметичность REST Tx B release-evidence тестов

В `tests/restTxbSingleEventCanary.test.ts` обнаружена причина двух внешних падений:
helper `copyAuthoritativeReleaseEvidence` копировал четыре файла из отсутствующего
абсолютного каталога `C:\VAMBAM\Projects\OTG\DEV\...`:

- `txa_canary_summary.json` — итоговые gates, счётчики, scope и provenance;
- `txa_canary_rows.jsonl` — 42 результата admission (16 inserted, 26 duplicate);
- `txa_canary_preflight.json` — исходный snapshot и эталонный source provenance;
- `txa_canary_postflight.json` — postflight-снимок, защищённый обязательным хешем.

Production-верификатор проверяет SHA-256 каждого файла, равенство provenance между
summary и preflight, точное окно и тип запроса, COMPLETE/transport/semantic/Tx A
флаги, счётчики событий и admission, длины списков ID, состав 42 строк, отсутствие
Tx B/state/order/stream действий и успешную запись evidence. Combined SHA-256
строится детерминированно из отсортированных имён и файловых хешей. Фиксированные
исторические хеши показывают, что исходный тест доказывал совместимость именно с
историческими байтами, одновременно проверяя общий контракт.

Точная архивная копия найдена только в пределах `C:\VAMBAM\Projects\OTG\DEV\archive`.
Проверка структуры и маркеров секретов не выявила ключей, credential URL или известных
токенов. Однако evidence содержит реальные агрегаты БД, event IDs, dedupe keys и
provenance. Эти производственные данные не перенесены в публичный проект.

Вместо копирования создан `syntheticReleaseEvidence`: детерминированный test-only
builder пишет минимальные синтетические версии четырёх артефактов во временный
каталог, вычисляет их настоящие SHA-256 и регистрирует очистку. Общая строгая часть
валидатора выделена в `verifyRestTxbReleaseEvidenceFiles`. Production-функция
`verifyRestTxbReleaseEvidence` по-прежнему вызывает её только с прежним закрытым
манифестом четырёх исторических хешей; канарейки и production-default не изменены.
Общий валидатор дополнительно требует точный набор четырёх имён.

Тесты используют реальный валидатор, не подменяют результат и не обходят хеши.
Проверяются принятие COMPLETE evidence и повторяемость, отказ production-default
от синтетических байтов, удалённый файл, байтовая подмена, согласованно перехешированная
ложная полнота и отсутствие вызова Tx B/изменения fake pool. Существующие проверки
candidate incomplete и non-SAFE сохранены. Других абсолютных ссылок `C:\VAMBAM`
или `Projects\OTG\DEV` в tests нет.

Изменены `src/canary/restTxbSingleEventCanary.ts`,
`tests/restTxbSingleEventCanary.test.ts` и эти два существующих отчёта. Изменение
production-файла является рефакторингом общей проверки; поведение публичного
production-входа и release gate не менялось. Build и typecheck прошли. Два целевых
теста отдельно скомпилированы в игнорируемый `.cache` и выполнены через Node:
2/2 PASS. Полный `npm test` внутри Codex не запускался повторно и PASS не заявляется,
поскольку подтверждённый sandbox-сбой tsx остаётся. Требуется внешний `npm test`.
Git init, commit и push не выполнялись.
